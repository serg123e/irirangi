# Аудит проекта Irirangi

**Дата:** 2026-02-10
**Проект:** Интернет-радио, управляемое Telegram-ботом
**Стек:** Python 3.9, MPD, Icecast, Docker Compose, yt-dlp

---

## Обзор архитектуры

4 Docker-контейнера: `bot` (Python), `mpd` (музыка), `mpd-voice` (голос), `icecast` (стриминг).
Цепочка fallback: `/irirangi` → `/voice` → `/live` → `/music` → jingle-заглушка.

---

## Найденные проблемы

### КРИТИЧЕСКИЕ — Безопасность

#### 1. Захардкоженные пароли
**Файлы:** `icecast.xml:19-22,44,55,65,75`, `mpd.music.conf:34`, `mpd.voice.conf:31`
Пароль `hackme` записан прямо в конфигурационных файлах, которые находятся в git-репозитории. Любой, кто получит доступ к репозиторию, получит полный контроль над Icecast (admin, source, relay).

**Решение:** Вынести пароли в переменные окружения. Использовать `.env` файл (добавленный в `.gitignore`) и подстановку переменных в `docker-compose.yml`. Для `icecast.xml` — использовать `envsubst` или шаблон при старте контейнера.

#### 2. Инъекция команд через URL
**Файл:** `app/bot.py:121-124`
URL из сообщений Telegram передаётся напрямую в `subprocess.check_output` через `yt-dlp`. Хотя используется список аргументов (а не shell=True), сам URL не валидируется — возможны нежелательные аргументы yt-dlp и злоупотребления.

**Решение:** Строгая валидация URL по whitelist доменов (youtube.com, youtu.be, soundcloud.com). Отклонять URL с подозрительными символами.

#### 3. Отсутствие авторизации
**Файл:** `app/bot.py` (весь файл)
Любой пользователь Telegram может управлять ботом — добавлять треки, останавливать воспроизведение, удалять из плейлиста. Нет ограничений по chat_id или user_id.

**Решение:** Добавить whitelist разрешённых chat_id/user_id через переменные окружения. Проверять доступ в каждом обработчике.

#### 4. Path traversal через имена файлов
**Файл:** `app/bot.py:87-88,94-95`
Имя файла берётся из `file_path.split("/")[-1]` без санитизации. Telegram контролирует file_path, но filename передаётся в mpc и ffmpeg без проверки — возможны специальные символы.

**Решение:** Санитизация имён файлов — удалять `/`, `..`, null-байты; использовать `secure_filename()` или uuid.

---

### ВЫСОКИЕ — Надёжность

#### 5. Блокирующие вызовы в async-контексте
**Файл:** `app/bot.py:34-40` (`time.sleep`), `bot.py:97,124` (`subprocess.check_output`)
Все вызовы `subprocess.check_output()` и `time.sleep()` блокируют event loop asyncio. При долгом скачивании (до 300 секунд) бот перестаёт отвечать всем пользователям.

**Решение:** Заменить `subprocess.check_output` на `asyncio.create_subprocess_exec`. Заменить `time.sleep` на `asyncio.sleep`. Или выносить блокирующие операции в `loop.run_in_executor()`.

#### 6. Версии зависимостей не зафиксированы
**Файл:** `requirements.txt`
`python-telegram-bot` и `yt-dlp` указаны без версий. Мажорное обновление `python-telegram-bot` (v13 → v20) ломало API. `yt-dlp` обновляется часто и может менять поведение.

**Решение:** Зафиксировать версии: `python-telegram-bot==20.x`, `yt-dlp==2024.x.x`. Добавить `requirements.lock` или использовать poetry/pip-compile.

#### 7. Нет управления дисковым пространством
**Файлы:** `app/bot.py:88,96`, `/music/`, `/voice/`
Скачанные файлы накапливаются бесконечно. При заполнении диска все сервисы упадут.

**Решение:** Добавить ротацию файлов — удалять файлы старше N дней или при превышении лимита. Реализовать как cron-задачу или периодическую задачу в боте.

#### 8. Временные файлы не удаляются
**Файл:** `app/bot.py:95-97`
Голосовые сообщения скачиваются в `/tmp/`, обрабатываются ffmpeg, но оригинал не удаляется.

**Решение:** Добавить `os.remove()` для временного файла после обработки. Использовать `tempfile.NamedTemporaryFile` с автоудалением.

#### 9. Нет health checks в Docker
**Файл:** `docker-compose.yml`
Контейнеры не имеют проверок здоровья. Docker не может обнаружить зависшие процессы и перезапустить их.

**Решение:** Добавить healthcheck для каждого сервиса:
- `icecast`: `curl -f http://localhost:8000/status.xsl`
- `mpd/mpd-voice`: `mpc status`
- `bot`: проверка процесса python

#### 10. Нет зависимостей между сервисами
**Файл:** `docker-compose.yml`
Бот запускается без ожидания готовности MPD и Icecast. Если бот стартует первым — `mpd_init()` упадёт.

**Решение:** Добавить `depends_on` с `condition: service_healthy` (требует healthchecks). Как минимум — добавить `depends_on` без condition.

### СРЕДНИЕ — Качество кода и архитектура

#### 11. Нет обработки ошибок ffmpeg
**Файл:** `app/bot.py:96-97`
`subprocess.check_output` для ffmpeg не обёрнут в try/except. При ошибке конвертации — необработанное исключение.

**Решение:** Обработать CalledProcessError и сообщить пользователю о проблеме.

#### 12. Нет настройки логирования
**Файл:** `app/bot.py`
Используется `logging.error/warning`, но `logging.basicConfig()` не вызывается. Формат, уровень и вывод логов не настроены.

**Решение:** Добавить `logging.basicConfig(level=logging.INFO, format='%(asctime)s %(levelname)s %(message)s')`.

#### 13. Docker Compose версия устарела
**Файл:** `docker-compose.yml:1`
`version: '3.8'` — устаревший формат. Современный Docker Compose игнорирует это поле.

**Решение:** Удалить строку `version`, использовать формат Compose Specification.

#### 14. Непиннированные базовые образы
**Файлы:** `Dockerfile.icecast:1`, `Dockerfile.music.mpd:1`, `Dockerfile.voice.mpd:1`
`alpine:latest` может сломать сборку при обновлении Alpine. `python:3.9-alpine` — лучше, но 3.9 уже EOL.

**Решение:** Использовать конкретные теги: `alpine:3.19`, `python:3.11-alpine3.19`.

#### 15. Дублирование Dockerfile'ов MPD
**Файлы:** `Dockerfile.music.mpd`, `Dockerfile.voice.mpd`
Два почти идентичных Dockerfile с минимальными отличиями (один использует `--stderr`, другой `--stdout`).

**Решение:** Объединить в один Dockerfile с build-arg для выбора режима.

#### 16. Пустой ответ при пустом плейлисте
**Файл:** `app/bot.py:210-211`
Если плейлист пуст, `mpc_command("playlist")` возвращает пустую строку — Telegram API выбросит ошибку (пустое сообщение запрещено).

**Решение:** Проверять пустой ответ и отправлять "Playlist is empty".

#### 17. Нет restart policy для всех сервисов
**Файл:** `docker-compose.yml`
Только `bot` имеет `restart: unless-stopped`. Остальные сервисы не перезапускаются при падении.

**Решение:** Добавить `restart: unless-stopped` для `icecast`, `mpd`, `mpd-voice`.

### НИЗКИЕ — UX и документация

#### 18. Нет команды /help
**Файл:** `app/bot.py:219-236`
Пользователи не знают, какие команды доступны.

**Решение:** Добавить обработчик `/help`, выводящий список команд с описанием.

#### 19. Опечатки в README
**Файл:** `README.md:7,11`
"soudcloud" → "soundcloud", "immediatelly" → "immediately".

**Решение:** Исправить опечатки.

#### 20. Закомментированный мёртвый код
**Файл:** `app/bot.py:107,110,112-113,130,237`
Множество закомментированных строк, не несущих смысловой нагрузки.

**Решение:** Удалить мёртвый код. История сохранена в git.

#### 21. Нет .env.example
Есть `bot.env` в `.gitignore`, но template-файл (`bot.env`) с плейсхолдером всё равно в репо. Это не стандартный подход.

**Решение:** Переименовать в `bot.env.example`, обновить .gitignore и README.
